Summary

GymBro is a voice-first lifting tracker: say what you just lifted, hear a ping, keep training. It remembers every set, tells you what you did last time, and asks when you're ready to add weight.

Hackathon scope: a mobile web app for Android Chrome, built solo, demo-ready by 15:00 on 28 Oct 2026.

Problem and target user

People who lift regularly know they should track their sets, but typing weights and reps into an app between sets is too fiddly, so they stop tracking. Without a log they can't remember last session's numbers and don't know when to add weight.

Target user: a regular gym-goer doing a push / pull / legs style routine with an Android phone and headphones, music playing. Today they track nothing.

Job to be done: "Between sets, with chalky hands and music on, let me record what I did in one sentence, and tell me when I've earned a heavier weight."

Goals, non-goals and demo success

Goals

  • Log a set by voice in one sentence, with no typing or tapping.
  • Recall the last weight and best reps for any exercise, by voice.
  • Prompt a weight increase when the user has earned it.
  • Group sets into automatically named sessions (for example "Wed Push").

Non-goals for today

  • Native Android app, background listening with the screen locked, or lowering other apps' music volume.
  • Accounts, cloud sync, or multiple users.
  • Workout planning, programmes, nutrition, or social features.

Demo success criteria

  • Say a set with the wake word on a propped-up phone and hear the ping within about 2 seconds.
  • Leave out the equipment and get asked for it.
  • Ask "what did I do last time?" and hear a correct spoken answer.
  • Load demo data and see the progression prompt fire.
  • Show history grouped by session and by exercise.

Core user flow

Every interaction starts with the wake word. A normal log ends in a ping. GymBro only talks when it needs an answer or you asked it something.

Example exchange

  • GymBro, bench press, 20 kg, going for 12, got 9.
  • Bar, dumbbells or machine?
  • Bar. (ping)
  • GymBro, what did I do last time on bench?
  • You're on 25 kg, your best is 11 reps.

Progression rules

GymBro asks to add weight once the user hits the top of their rep range on every set, at the same weight, for 2 weeks in a row.

  • Tracked per exercise and equipment. Barbell bench and dumbbell bench are separate lifts.
  • Target reps = the "going for" number the user says, e.g. 12. If it's left out, use the last target for that lift.
  • Qualifying week = a session in which every set at the working weight reached the target.
  • Trigger: 2 qualifying sessions in 2 consecutive calendar weeks.
  • When it asks: on the first set of that lift in the next session. "You've hit 12 on bench two weeks running. Want to go up to 22.5 kg?"
  • Yes sets the new working weight. No waits for another qualifying week before asking again.

Default increments

Common strength-coaching rules of thumb, approximate; editable in code.

Lift typeEquipmentIncrement
Lower-body compound (squat, deadlift, RDL, hip thrust)Barbell+5 kg
Upper-body compound (bench, overhead press, row)Barbell+2.5 kg
AnyDumbbell+2 kg per dumbbell (next pair up)
Lower-body (leg press, leg extension, leg curl)Machine+5 kg (one plate on the stack)

Isolation (curls, lateral raises, triceps)AnySmallest available step, typically +1 to +2 kg

The parser tags each exercise with a lift type (lower compound, upper compound, isolation) and a push / pull / legs group. The increment comes from that tag plus the equipment.

Screens

There are three screens, all designed for one-handed, glance-from-a-bench use: large type, high contrast.

  1. Live (home)
    • Listening indicator: idle, heard wake word, thinking, logged (with the ping).
    • Today's session title ("Wed Push") and its sets, newest on top.
    • Last transcript and how it was parsed, so mistakes are visible.
    • Big tap-to-talk button.
  2. History
    • Toggle between By session and By exercise.
    • By session: list of sessions ("Wed Push · 28 Oct · 14 sets"), tap to see sets grouped by exercise.
    • By exercise: each lift with current working weight, best reps, and every session's sets in date order.
  3. Settings
    • API key (stored only on the device).
    • Units (kg by default).
    • Load demo data, and clear all data.

Technical approach

GymBro is a static web app with no backend: everything runs in Android Chrome and the only planned network call is to the Claude API.

API key: entered in Settings and kept on the phone. Calling Claude from the browser exposes the key to anyone with the device, which is acceptable for a personal hackathon demo, not for launch.

Parser contract

Send the transcript plus context (last set, today's lifts, any pending question). The parser returns exactly one intent:

  • log_set: exercise (normalised name), equipment or null, weight, unit, target reps, actual reps, lift type, push / pull / legs group.
  • query_last: exercise.
  • answer_equipment, answer_yes_no: replies to a question GymBro asked.
  • undo, unknown.

Data model

  • Set: id, timestamp, sessionId, exercise, equipment, weightKg, targetReps, actualReps, liftType, group.
  • Session: id, startedAt, title (derived from weekday + majority group).
  • Lift state (key = exercise + equipment): workingWeightKg, bestReps, lastPromptWeek.

Build plan, risks and v2

Build the riskiest part first: voice on a real phone. Freeze features about an hour before 15:00 and spend the rest testing and rehearsing.

  1. Voice spike (first ~30 min). Deploy a bare page to GitHub Pages, open it on an Android phone with music playing, and confirm continuous listening, the wake word, and what happens to the music.
  2. Parse and log. Parser, save sets, ping, tap-to-talk fallback (F1–F5, F13).
  3. Recall. "What did I do last time?" and the equipment follow-up question (F4, F6).
  4. Sessions and history. Auto-grouping and the History screen (F9, F10).
  5. Progression. Rule, increments table, yes / no prompt, demo data seeding (F8, F14).
  6. Feature freeze, then polish. P1 items only if time allows, then test in a noisy room and rehearse a 2-minute demo script.

v2 ideas

  • Native Android app for true pocket mode: background wake word, music ducking via audio focus, headphone-button trigger.
  • On-device wake word (Picovoice Porcupine) and offline parsing.
  • Rest timer started automatically after each logged set.
  • Accounts and sync, so history survives a new phone.
  • Charts of working weight per lift over time.
